# Hammerspoon config inventory

Date: 2026-10-07. Read-only survey of `~/Github/hammerspoon` (which `~/.hammerspoon` symlinks to) and the symlinked voice agent files in `~/Github/pipecat-voice-agent/hammerspoon`. The question it answers: what each feature does, how it fires, which `hs.*` APIs it needs, and how hard it would be to run it somewhere other than Hammerspoon.

## How the config is put together

- `init.lua` loads `hs.ipc` (so `hs -c '<lua>'` works from a shell), then `lib/plugins.loadAll()` with a fixed order for dictation, brown_noise, noseguard, tts, lmstudio, dsh, shokz_mute, keystroke_typer and voice_agent. Anything else under `apps/` loads after them, alphabetically. Then `plugins.install()` adds the Plugins tile.
- `lib/plugins.lua` treats `apps/<name>/init.lua` and `apps/<name>.lua` as plugins. It requires each inside `pcall`, keeps the disabled set in `hs.settings` (`plugins.disabled`), and calls `dispose()` when a plugin is switched off.
- `lib/context.lua` wraps the `hs.*` constructors (`timer`, `after`, `task`, `hotkey`, `url`, `atExit`, `tile`) and records a teardown for each, so `ctx:dispose()` undoes everything. It also fans out the single `hs.shutdownCallback` slot to every plugin. Only keystroke_typer, noseguard, dsh and the Plugins tile use it. dictation, tts, brown_noise, lmstudio, shokz_mute and voice_agent call `hs.*` directly.
- `lib/spoon.lua` can load a third-party Spoon into a context, but nothing calls it and `Spoons/` is empty.
- `lib/menuhub.lua` is the single menu-bar item. Every app calls `hub.item(name)` or `ctx:tile(name)` and gets a proxy with the `hs.menubar` methods (`setTitle`, `setIcon`, `setMenu`, `setTooltip`, `setClickCallback`), so no app creates its own status item. The voice agent falls back to `hs.menubar.new()` only if the hub fails to load.
- Pure, `hs`-free modules sit next to the wiring and have busted specs: `lib/stt_server`, `lib/tts_core`, `lib/teams_api`, `lib/hfp_mute`, `lib/earcon`, `lib/lmstudio`, `lib/dsh`, `lib/voice_toggle`, plus `keystroke_typer.plan/clusters`.

## The pop-up at the top of the screen

The pop-up is the menu hub panel. `lib/menuhub.lua` draws it from `lib/menuhub_panel.html`.

- **Trigger.** A plain click on the 🔨 menu-bar item calls `M.togglePanel()`. Option-click skips the panel and pops a native `NSMenu` dropdown built from the same entries (`M.build`), using a hidden `hs.menubar.new(false)` and `:popupMenu(point)`. That dropdown has "Reload Hammerspoon" and "Open console" as a footer.
- **Window.** The panel is an `hs.webview`, borderless, transparent, with a system shadow and `allowTextEntry(true)`. It sits at `hs.drawing.windowLevels.popUpMenu`, with behaviour `canJoinAllSpaces + transient`. A `windowCallback` hides it when it loses focus, so it closes like a real menu. On open it calls `hs.focus()` and focuses its own window.
- **Placement.** It is 360 px wide. Its right edge lines up with the right edge of the 🔨 item, it sits 6 px below the menu bar, and it is clamped 8 px inside the screen that holds the menu bar (`hs.screen.allScreens`). The height comes from the page (`{cmd:"size", h}`) and is capped at 640 px and at the bottom of the screen. When the menu bar is auto-hidden it anchors to where the bar would be.
- **Home view.** A card with an 18 px radius and a 2-column grid of tiles, each 58 px tall with a 14 px radius. A tile shows the app's glyph (its `setTitle` emoji, or its `setIcon` image encoded as a data URL) in a round disc, the app name, and a one-line status taken from the first line of the app's tooltip, with a repeated app-name prefix removed (`M.statusOf`). A `›` chevron marks tiles that have a menu. The header shows "N apps". The page follows `prefers-color-scheme`, with Apple-like colours, an `#007aff` accent and green switches.
- **Detail view.** Clicking a tile replaces the grid with that app's menu, drawn the same way. It has a back button and breadcrumbs, a hero disc, and grouped rows. Rows can be separators, info lines, actions, ✓ check rows, drill-in submenus, on/off switches (`switch = true`) and sliders (`slider = {value,min,max,step,unit,fn}`). Rows that an app ticks by hand with "✓ " text become check rows (`M.items`).
- **Bridge.** JS calls `window.webkit.messageHandlers.hub.postMessage` (an `hs.webview.usercontent` named `hub`). Lua handles `ready`, `size`, `close`, `open`, `back`, `item`, `slide`, `reload` and `console`, and pushes state back with `evaluateJavaScript("render(<json>)")`. Any proxy setter triggers a redraw coalesced to 50 ms. After an action runs, the panel redraws 100 ms later. Slider drags call the app's `fn` live without a redraw, so the thumb does not jump.

Other overlays that are not at the top: the dictation HUD and toast are `hs.canvas` panels in the middle of the screen, the live transcript is an `hs.canvas` 120 px above the bottom, `hs.alert` draws its default centred banners, and NoseGuard's red flash is a separate Swift binary covering the whole screen.

## Inventory

Classes: **A** process supervision, HTTP or timers that any Node host can do. **B** needs a tray or menu-bar UI, overlay windows or notifications. **C** needs OS input hooks (global hotkeys, Fn or modifier taps, synthetic keys or paste) or accessibility. **D** needs system event watchers (audio devices, sleep and wake, app focus).

Each row gets the class of the hardest thing that feature needs, with one exception: the hub tile is counted once, in row 1. Every app below also draws a tile, so all of them need row 1 to move first.

## Hardest to move

1. **Hold-Fn dictation with paste (rows 3 and 4).** It needs a session-level `CGEventTap` on `flagsChanged` to see Fn alone, including key-up, and a keyDown tap that can swallow Fn+C and Fn+S. Electron's `globalShortcut` and similar APIs cannot bind a bare modifier or report releases, so a new host needs a native helper with Accessibility and Input Monitoring permission. The microphone permission currently belongs to Hammerspoon as the responsible process for `ffmpeg`, so the new host must request it again. The paste at the end is a synthetic ⌘V.
2. **Speak the selection (row 9).** It runs inside that same event tap. It posts a synthetic ⌘C one tick later, watches `NSPasteboard.changeCount`, and snapshots and restores every pasteboard flavour (`readAllData` and `writeAllData`) so images and rich text survive. Node has no built-in way to do any of the three.
3. **Keystroke typer (row 16).** It posts `CGEvent` key events carrying arbitrary Unicode strings with modifier flags cleared, checks live modifier state, and arms a global Escape only while typing. Libraries such as nut.js cover part of this, but not the per-event Unicode string with cleared flags. Shokz mute (row 15) is close behind, because its working path posts ⌘⇧M to the Teams process rather than to the focused app (`CGEventPostToPid`).

The hub panel (row 1) is not on this list. It is B, and its HTML and message protocol could move to a tray app with little change.
